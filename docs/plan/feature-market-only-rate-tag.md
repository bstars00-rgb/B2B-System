# 기능 기획 — 마켓 전용요금 태그 (Market Only Rate)

> **작성일**: 2026-10-20 · **트랙**: B (Marketplace 고도화) · **차수**: 번외 작업(고도화 차수와 별도) · **상태**: 결정 반영(2026-10-20) + 프로토타입 시안
> **요청 출처**: 현업(2026-10-20). ELLIS의 마켓 전용요금 설정(ELS-3838, PROD 2026-10-15)은 배포 완료. 마켓에서 요금을 검색할 때 고객이 전용요금이라는 것을 바로 알아보도록 태그를 단다.
> **참고 자료**: `Dotbiz_Market_Only_Rates_User_Guide.pptx` (SCM용 사용 가이드 v1, 2026-10-19)

---

## 0. 한 줄 요약

ELLIS의 Dotbiz Market 트레이더(comp code 300427)에 Include로 넣은 레이트플랜·프로모션은 이미 마켓에서만 팔린다. 이 요금에 마켓 검색 화면에서 **"Market Only"** 태그 하나를 단다. 가격 비교 문구는 넣지 않는다.

## 1. 현재 상태 (배포된 기능)

| 항목 | 내용 |
|------|------|
| 설정 위치 | ELLIS Users > Customer > Traders > Dotbiz Market(300427, 상태 Pending 유지) > Seller 탭 |
| Include | Seller Include Info의 Rate Plans List·Promotion List. 마켓 에이전시 전체에 노출되고 B2C(www.ohmyhotel.com)와 API/OTA에는 노출되지 않는다 = 마켓 전용 |
| Exclude | Seller Exclude Info. 마켓에서만 숨긴다 |
| 반영 | 저장 후 2~3분, 약 640개 셀러에 적용 |
| 규칙 충돌 | 트레이더 규칙과 에이전시 규칙이 같은 요금에서 부딪치면 Exclude 우선 |
| 알려진 이슈 | 신규 에이전시는 트레이더를 다시 저장해야 규칙을 받는다(별도 수정 예정) |
| 마켓 화면 | 전용요금이 일반 요금과 똑같이 보인다. 실포털 룸 리스트의 태그는 프로모션 태그(Special Promotion, Basic Promotion, 초록 바탕)뿐 |
| 사용량 점검 | 2026-10월 말, 전용 설정 건수와 예약 여부 (PD Tracy) |

## 2. 목표와 지표

**목표**: 에이전시가 검색 결과에서 전용요금을 바로 알아보고 고르게 한다. 호텔에서 받아 온 전용요금이 예약으로 이어지게 한다.

| 지표 | 정의 |
|------|------|
| 선택률 | 전용요금 노출 대비 Select 비율 (일반 요금과 비교) |
| 예약 전환 | 전용요금 예약 건수·예약액, 마켓 전체 대비 비중 |
| 공급 | 전용요금이 설정된 호텔 수·요금 수 (SCM 설정 활동) |
| 기준선 | 10월 말 사용량 점검 결과 (태그 도입 전 값) |

## 3. 태그 정의

### 3.1 대상

트레이더 300427 Include(Rate Plans List·Promotion List)에 들어 있고, 검색한 에이전시에 노출되는 요금. 판정은 ELLIS가 노출 여부를 계산할 때 쓰는 규칙을 그대로 쓰고, 마켓 화면은 따로 판정하지 않는다. 에이전시가 Exclude한 요금은 화면에 나오지 않으므로 대상이 아니다.

에이전시 자체 Include 요금(그 에이전시만 보는 요금)에는 태그를 달지 않는다(2026-10-20 결정).

### 3.2 태그

| 표시 조건 | 문구 | 툴팁(마우스 오버) |
|-----------|------|-------------------|
| 대상 요금이면 항상 | Market Only | Dotbiz Market 전용 요금입니다. B2C 사이트와 API·OTA 채널에서는 판매하지 않습니다. |

가격 비교 문구("일반 요금보다 저렴", 할인율 %, "최저가", "Best Price")는 넣지 않는다(2026-10-20 결정). 마켓 전용요금은 같은 호텔의 일반 요금보다 높을 수도 낮을 수도 있어 가격을 단정할 수 없다. 태그는 판매 채널(마켓 전용)만 알린다.

### 3.3 문구 (포털 6개 언어)

| 언어 | 태그 | 필터 |
|------|------|------|
| English | Market Only | Market Only rates |
| 한국어 | 마켓 전용 | 마켓 전용 요금 |
| 日本語 | マーケット限定 | マーケット限定料金 |
| Tiếng Việt | Chỉ có trên Market | Giá chỉ có trên Market |
| 中文 | 市场专享 | 市场专享价 |
| 繁體中文 | 市場專享 | 市場專享價 |

### 3.4 디자인

- 진한 남색 바탕에 흰 글자. 실포털 프로모션 태그(초록 바탕), 추천·오피포인트 배지(주황)와 색이 겹치지 않게 했다.
- 다크모드에서도 같은 대비를 유지한다.

## 4. 노출 위치

| 화면 | 표시 | 비고 |
|------|------|------|
| Create Booking 검색 결과 호텔 카드 | 전용요금이 1개 이상이면 태그 (Hotel Code 옆) | 카드 가격은 지금처럼 호텔 최저가 |
| Create Booking 왼쪽 필터 | "Market Only rates" 체크박스와 해당 호텔 수 | 결과에 전용요금 호텔이 있을 때만 보인다 |
| 룸 리스트 요금 행 | 태그 | 실포털 프로모션 태그와 같은 줄, 맨 앞. 행 순서는 가격 낮은 순 그대로 |
| Create Hotel Booking 모달 | Plan Name 옆 태그 | 예약 직전에 한 번 더 확인 |
| Bookings 목록·상세 | 태그 (예약 당시 값) | CS·성과 집계용 |
| 바우처 | 표시하지 않음 | 투숙객용 문서 |
| OHMY Admin(ELLIS) > 예약 생성 | 이번 작업에서 표시하지 않음 | 고객 화면용 태그. 제안이며 확정 필요(§10) |

요금은 항상 가격 낮은 순(Billing Sum)으로 보여 주고, 전용요금이라고 위로 올리지 않는다(2026-10-20 결정). 호텔 목록 정렬(Recommendation 등)도 그대로 둔다.

## 5. 데이터·API

| 항목 | 내용 |
|------|------|
| 판정 플래그 | ELLIS 가용성 응답의 요금 단위에 `exclusiveChannel: "DOTBIZ_MARKET" \| null` 추가. 이 요금이 트레이더 300427 Include 때문에 노출되면 값이 들어간다. 프로토타입 필드명은 `market_only` |
| 프로모션 | 프로모션만 Include면 그 프로모션 요금에만 태그(원 레이트플랜·다른 프로모션은 태그 없음). 레이트플랜 전체가 Include일 때 그 위의 프로모션은 실제 판매 범위를 따른다(§10 Tracy에게 역질문) |
| 예약 저장 | 예약 생성 시 요금 플래그를 예약에 저장(`rateFlags.marketOnly`). 이후 트레이더 규칙이 바뀌어도 예약 당시 값을 유지 |
| 반영 시점 | 트레이더 저장 후 2~3분(지금과 같음). 이미 띄운 검색 결과는 재검색 때 반영 |
| 로그 | 노출·선택·예약 이벤트에 플래그를 남긴다(§2 지표) |

## 6. 예외 처리

| 상황 | 처리 |
|------|------|
| 트레이더 Include + 에이전시 Exclude | 요금이 보이지 않으므로 태그도 없음 |
| 트레이더 Exclude + 에이전시 Include (가이드 E 케이스) | 어느 채널에서도 팔리지 않으므로 해당 없음 |
| 신규 에이전시(트레이더 재저장 전) | 전용요금이 보이지 않으므로 태그도 없음. ELLIS 수정 태스크가 끝나면 함께 해결 |
| 전용요금이 일반 요금보다 비싸거나 같음 | 태그는 그대로. 가격과 관계없이 판매 채널만 알린다 |

## 7. 프로토타입 시안 (2026-10-20)

| 항목 | 내용 |
|------|------|
| 시연 호텔 | Sotetsu Fresa Inn Tokyo-Akasaka(168085)·Daiwa Roynet Hotel Osaka Uehonmachi(453378)는 전용요금이 일반 요금보다 낮은 예, Sotetsu Fresa Inn Tokyo-Tamachi(304417)는 더 높은 예. 태그는 셋 다 같다 |
| 화면 | Create Booking(도쿄·오사카 검색) 호텔 카드·필터, 룸 리스트(가격 낮은 순), 예약 모달. 포털 언어 설정에 따라 6개 언어 |
| 코드 | `mocks/marketOnlyRates.ts`(시연 규칙) · `components/MarketOnlyTag.tsx`(태그·문구) · `RateResult.market_only` |
| 폐기 | 위 두 파일 + 화면 4곳의 태그 줄 + `hotelDb.ts`의 `withMarketOnly` 2곳 |

프로토타입은 요금이 생성형 목데이터라, 시연 호텔의 기준 레이트플랜을 복제해 전용 레이트플랜(이름 "스마트 플렉시블")을 하나 추가했다. 실서비스에서는 ELLIS 플래그만 읽는다.

## 8. 결정 (2026-10-20)

| # | 항목 | 결정 |
|---|------|------|
| 1 | 태그 이름 | **Market Only** (한국어 "마켓 전용") |
| 2 | 가격 비교 문구 | 넣지 않는다. 마켓 전용요금이 일반 요금보다 높을지 낮을지 단정할 수 없다 |
| 3 | 에이전시 자체 Include 요금 태그 | 필요 없음 |
| 4 | 정렬 | 요금은 항상 가격 낮은 순. 전용요금을 위로 올리지 않는다 |
| 5 | 차수 | 번외 작업(고도화 차수와 별도) |

**확인 필요**: 레이트플랜 전체가 Include일 때 그 위의 프로모션도 전용으로 볼지(ELS-3838 동작, Tracy). 확인 전까지는 프로모션 자체가 Include인 경우만 태그를 단다.

## 9. 진행 제안

번외 작업으로 진행한다.

1. ELLIS: 가용성 응답에 판정 플래그 추가(§5)
2. 마켓: 태그(호텔 카드·룸 리스트·예약 모달) + 필터 + 예약 저장
3. 마켓: Bookings 목록·상세 표시, 지표 로그
4. SCM 가이드에 "에이전시 화면에 보이는 태그" 슬라이드 추가
5. 10월 말 사용량 점검 결과를 기준선으로 도입 후 효과 비교

## 10. PD 질의응답 (2026-10-20, Tracy)

| # | Tracy 질문 | 회신 |
|---|-----------|------|
| 1 | 태그는 ohmyhotel.biz 검색 결과·객실 목록에만인가, OHMY Admin > 예약 생성에도인가 | ohmyhotel.biz만: 검색 결과(호텔 카드·필터), 객실 목록, 예약 확인 팝업, Bookings. OHMY Admin 예약 생성은 이번 작업에서 제외(제안, 확정 필요) |
| 2 | 프로모션만 Include일 때 그 프로모션 가격에만 표시하나 | 그렇다. 원 레이트플랜과 다른 프로모션에는 태그 없음. 역질문: 레이트플랜 전체가 Include일 때 그 위 프로모션(같은 Origin Plan Code)도 B2C·API에서 숨겨지는가. 숨겨지면 태그, B2C에 팔리면 태그 없음 |
| 3 | 라벨이 "Dotbiz Market"인가 다른 것인가 | "Market Only" 하나(포털 언어별 번역은 §3.3). 가격 비교 문구는 없음 |
