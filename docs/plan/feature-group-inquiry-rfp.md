## 0. 한 줄 요약

**고객사가 마켓플레이스에서 "단체 문의"를 넣으면 → 메일로 우리에게 접수되고 → 우리가 호텔들에게 역경매(RFP)로 뿌려 견적을 회수 → 각 호텔 견적에 우리 마크업을 자동으로 얹어 고객사에 리스트업 → 고객사가 선택하면 리퀘스트 예약으로 진행**하는 기능.

- **핵심 1**: 즉시 예약이 아니라 **리퀘스트(문의) 기반**. 접수는 **메일 알림**으로 시작.
- **핵심 2**: 우리가 중간에서 일일이 처리하지 않고 **호텔들에게 역경매로 뿌린다**(호텔이 자기 컨디션에 맞춰 견적).
- **핵심 3**: 호텔 견적은 **우리 마크업 불포함일 수 있다** → 시스템이 **마크업을 자동으로 얹어** 고객 안내가 나가야 하고, 그 마크업은 **일률적으로 설정** 가능해야 한다.

## 1. 배경과 목적

### 1.1 문제 인식
- 단체(스포츠팀·행사·MICE 등)는 **다실·특수요건**(장소 인접·특정 룸믹스·총예산)이라 **즉시 예약 흐름에 맞지 않는다.** ✅ **그룹 예약 = 동일 호텔 5실 이상**(현업 확정 2026-10-01) — 즉시 예약은 **4실까지**, 5실 이상은 이 기능으로 접수한다.
- 지금은 이런 문의가 **오프라인/메일로 산발 접수**되고, 우리가 수작업으로 호텔을 물색·중개한다. 표준 접수 양식·역경매·마크업 자동화가 없다.

### 1.2 목적
- **표준 접수 양식**으로 단체 문의를 구조화(국가·지역·호텔·기간·룸믹스·예산·인원).
- **역경매 소싱** — 한 번의 문의를 다수 호텔에 뿌려 **호텔이 경쟁 견적**하게 함(우리 수작업 중개 최소화).
- **마크업 자동·일률 설정** — 호텔 net 가격에 우리 마진을 자동으로 얹어 고객 sell 가격 산출(요율·net 은닉).
- 리퀘스트 예약까지 **한 흐름**으로 연결.

### 1.3 다른 기획과의 관계
| 관계 | 내용 |
|------|------|
| 즉시 예약 객실 상한 | ✅ **4실까지**(2026-10-01, 기존 No.12의 5실 캡에서 조정) — Create Booking·룸리스트에 **"5실 이상? 단체 문의 →"** 연결 |
| 약관 제4조 ③ | 현행 문구 "4실 이상 = 그룹 예약" → **5실 이상으로 개정 필요**(Legal, §11). 단체 문의가 그 **공식 채널** |
| OP Points | 무관(리퀘스트 예약 확정 시 적립 대상 여부는 추후 — 지금 범위 밖) |

## 3. 전체 흐름

```mermaid
flowchart TD
    A["고객사: 단체 문의 작성<br/>(국가·지역·호텔?·기간·룸믹스·예산·인원)"] --> B["제출 → 메일로 우리에게 접수"]
    B --> C["우리: 대상 호텔 선정 후<br/>역경매 RFP 배포"]
    C --> D["호텔들: 컨디션대로 견적<br/>(net 가격·조건·취소규정)"]
    D --> E["시스템: 각 견적에<br/>우리 마크업 자동 적용<br/>net → sell"]
    E --> F["고객사: 견적 리스트업 조회<br/>(호텔 위치·컨디션·가격)"]
    F --> G["고객사: 선택 → 리퀘스트 예약"]
    G --> H["호텔: 리퀘스트 예약 수락<br/>→ 확정 / 거절"]
```

### 상태(Status) 정의
| 상태 | 의미 |
|------|------|
| `Draft` | 작성 중(작성 화면 — 임시저장은 미구현) |
| `Submitted` | 제출 완료 — **접수 메일 발송** |
| `Sourcing` | RFP 배포(견적 수집 중) — **제출 즉시 자동**(벤더 콘솔 도시 일치 호텔 + 메일·SCM) |
| `Quoted` | 견적 회수 + 요금 구조 적용 + **전부** 고객 리스트업 |
| `Requested` | 고객사 선택 = **리퀘스트 예약 생성**(호텔 응답 대기) ※ 기획 초안의 `Selected`는 선택 즉시 예약이 생성되어 여기에 통합 |
| `Accepted` | **호텔 수락 · 결제 대기** — 단체 예약 확인서(계약) 동의 + **N시간 내 결제** |
| `Confirmed` | **결제 완료 · 확정** |
| `Cancelled` | 문의 취소 — 사유: **호텔 거절**(초안의 `Declined`) / **결제 마감 경과 자동취소** / **고객사 취소**(취소 마감 전) |
| `Expired` | 회신 기한 경과 · 견적 없음(표시용 파생) |

> 상태 정렬 2026-10-01. 콘솔(호텔) 상태: 신규 → 견적 제출 → 낙찰·컨펌 대기 → **확정·결제 대기 / 확정·결제 완료** · 미선택 · 거절 · 취소 · 마감. Marketplace Bookings: 결제 전까지 `Requested`(호텔 수락 후 **결제 마감** 배지) → 결제 시 `Confirmed`·Fully Paid → 취소 시 `Cancelled`(결제 후 고객사 취소면 Refunded).

## 5-0. 양면(2-sided) 구조 — 셀러(Marketplace) + 호텔(Console) 〔2026-09-29 확정〕

역경매는 **두 시스템을 잇는 양면 구조**다. 지금까지 셀러 측만 봤으나, 호텔의 "요청 수신·경매 참여"는 **벤더(호텔) 콘솔**에서 일어난다.

| 시스템 | 대상 | 역할 | 상태 |
|--------|------|------|------|
| **Marketplace** (Ohmy Partners 셀러 포털) | 셀러(고객사·OP) | 단체 문의 **작성·접수** → 회수 견적 **리스트업·선택** → 리퀘스트 예약 | ✅ 프로토타입 |
| **Vendor Console** (호텔 콘솔, 별도 repo `Console`) | **호텔(벤더)** | RFP **수신** → 경쟁 견적 **제출(blind)/거절** → 낙찰 시 리퀘스트 예약 수락 | ✅ **Group RFP 화면**(라이브 `…github.io/Console/`) |

```mermaid
flowchart LR
    S["셀러: 단체 문의 작성<br/>(Marketplace)"] --> M["접수 · 대상 호텔 배포"]
    M --> C["호텔: RFP 수신 → 경쟁 견적 제출<br/>(Vendor Console · Group RFP)"]
    C --> L["마크업/커미션 산출 → 리스트업<br/>(Marketplace)"]
    L --> R["셀러 선택 → 리퀘스트 예약"]
    R --> C2["호텔 수락 → 확정<br/>(Vendor Console)"]
```

**⚠ 현실(현업 2026-09-29) — 채널을 좌우하는 전제:** **호텔은 우리 콘솔을 많이 쓰지 않고, 우리(SCM)도 콘솔 기능을 잘 모른다.** 콘솔 활용도 체감 **KR > JP(정산 프로그램으로 인식) > VN(뭔지 모름)**, 마켓 예약 비중도 낮음(≈1%). → 콘솔 네이티브 자율 경매(Group RFP)는 **KR 등 도입률 높은 곳** 우선, **VN 등은 이메일·SCM 중개**가 실질 기본. (별도 설문 조사는 이 결론으로 **생략** — 도입률 향상은 별도 과제.)

## 5. 역경매 · 견적 회수

- **한 문의 → 다수 호텔 배포.** 대상은 **기존 계약/마켓플레이스 호텔이 기본**이며 ⑴ 문의에서 호텔을 특정했으면 그 호텔(들), ⑵ 지역까지만이면 **해당 지역(±앵커 거리) 내 기존 호텔군.** **신규 소싱은 필수가 아니라 옵션**(해당 지역에 계약 호텔 재고가 부족할 때만 운영 판단으로 추가). 〔현업 확정 2026-09-21〕
- **지역 타깃팅 (현업 확정 2026-09-29):** ① **도시 일치 = 필수** — 부산 호텔에 서울 요청은 **발송하지 않음.** ② 세부 지역(구·동)·앵커가 다르면 **제외하지 않고 거리(km)를 표시**(방식 B) — "요청: 강서 · 우리 호텔: 명동 · 약 12km". 호텔이 거리 보고 스스로 판단(멀면 미참여/셔틀 제안), 셀러도 리스트업에서 거리로 고름. (경쟁 호텔이 많을수록 유리)
- 호텔 견적 1건 = **회수 금액(국가 요금 구조 기준) + 가용성 + 컨디션 + 취소 마감(호텔 지정) + 결제 마감(시간) + 유효기한.** 〔SCM①: 호텔 단체 견적은 NET 제공, 단 일본 등은 단가+커미션〕 유효기한이 지난 견적은 선택 불가.
- 호텔은 자기 사정대로 **수락(견적 그대로)/인상/인하** 가능. **견적 시 객실 홀드는 기본 안 함**(가용만 체크) — 홀드 필요는 문의에 기재 〔SCM③〕.
- 회수된 견적은 **국가별 요금 구조 산출 후**(§6) 고객사에 **리스트업**: *"어디 호텔은 위치가 이렇고, 컨디션·가격이 이렇다."*

**역경매 방식 — 결정 필요 (제안 기본값):**
| 논점 | 제안 기본값 | 대안 |
|------|-------------|------|
| 호텔이 서로 견적을 보는가 | **블라인드(sealed)** — 각자 독립 견적 | 오픈(경쟁가 노출) |
| 견적 마감 | ✅ **고객사 지정 회신 기한**(확정 2026-09-29) — 호텔은 기한 내에만 제출, 경과 시 **마감**(제출 불가). 양쪽 목록에 **남은 시간**(D-n·시간) 표시, 24h 미만 경고 | 무기한(선착 마감) |
| 고객 노출 큐레이션 | ✅ 회수 견적 **전부 자동 리스트**(확정 2026-10-01 — **결정권은 고객사**) | ~~우리가 필터 후 노출~~ |

## 6. 국가별 요금 구조 ⭐ (핵심) 〔SCM 확정 2026-09-22〕

> 호텔 요금 구조가 **국가마다 다르다.** 마크업 "글로벌 일률"이 아니라 **국가별**로 처리한다. 어느 쪽이든 고객에겐 **고객가(sell)만** 보이고 net·단가·마크업률·커미션율은 은닉(OP Points 요율 은닉과 동일).

| 국가 유형 | 호텔 회수 | 고객가(sell) | 우리 마진 | 예시 |
|-----------|-----------|--------------|-----------|------|
| **net 국가**(예: 한국) | **net(원가)** | `round(net × (1 + 마크업%))` | sell − net | net 100,000 · 마크업 12% → **112,000** (마진 12,000) |
| **단가+커미션 국가**(예: 일본) | **단가(판매가)** + 커미션 | `단가`(그대로) | `단가 × 커미션%` (호텔 지급) | 단가 100,000 · 커미션 10% → **100,000** (마진 10,000) |

- **국가별 설정**: ELLIS 내부에서 **국가마다 요금 구조(net/단가) + 값(마크업%/커미션%)** 을 설정. 국가 선택 시 문의 폼도 통화·안내가 해당 국가에 맞춰 달라진다 〔Aiden④〕.
- **접수 규칙**: net 국가는 **net 기준**, 단가 국가는 **단가+커미션 기준**으로 회수(혼용 시 이중 적용/누락 위험) → 접수 화면에 국가별 기준 명시.
- **은닉**: 고객·리스트업·리퀘스트 예약 어디에도 회수금액·마크업률·커미션율 비노출. 내부(오퍼레이션/ELLIS)만 확인.

## 6-2. 낙찰 · 예약 · 결제 · 정산 〔현업 확정 2026-09-29〕

낙찰 후 고객은 **리퀘스트 예약**으로 진행하고, **OMH가 대신 수금·지불(Merchant of Record)** 한다.

**흐름:** 셀러 견적 선택(낙찰) → Marketplace에 **리퀘스트 예약 생성**(고객가·상태 Requested) → 호텔이 **컨펌**(콘솔) → **단체 예약 확인서 동의 + 결제**(N시간 내) → 확정(Confirmed) → 정산.

| 단계 | 규칙 |
|------|------|
| **호텔 컨펌** | 리퀘스트 예약을 호텔이 **컨펌/거절**. **거절 시 → 문의 취소.** (차순위 자동제안 안 함) |
| **결제 시점** | **컨펌 후 결제.** 결제 전 **단체 예약 확인서(계약 조건) 동의 필수**. **컨펌 후 N시간 내 미결제 시 자동취소**(위약금 없음) — **N은 호텔이 설정**(기본 3h). 확정 = 결제 완료 시점(선불 계약서 제2조와 일치). 프로토타입 결제는 UI 시연(카드 입력 없음) |
| **취소 규정** | ✅ **호텔이 오퍼 때 취소 마감일 지정**(2026-10-01 · 프리셋 대체) — 빠른 선택(체크인 3·7·14일 전) 또는 **마감 없음**. 마감일 23:59까지 **예약 전체** 취소 = **전액 환불**(원결제 카드, 10영업일), **이후 취소 불가·환불 불가**(노쇼·부분 감소 포함). 마감 없음 = 결제 시점부터 취소·환불 불가. 부분 취소 없음 |
| **결제·정산(MOR)** | 고객사가 **OMH에** 결제(고객 통화) → OMH가 호텔에 정산(호텔 통화·환율, Billings 15일 주기). net국=호텔에 **net** 지불(마진=마크업) / 커미션국=호텔에 **단가−커미션** 지불(마진=커미션) |
| **취소 수수료** | ✅ 수수료 구간 없음 — 마감 전 전액 환불 / 마감 후 취소·환불 불가로 단순화(SCM① 해소) |

예) 커미션국 단가 590,000·커미션 10% → 고객 **590,000** 결제(OMH 수금) / 호텔 **531,000** 수령 / OMH 마진 59,000. net국 net 100,000·마크업 12% → 고객 **112,000** / 호텔 **100,000** / 마진 12,000.

> **양면 반영(구현·배포 — 2026-10-01 실연동으로 갱신, §6-3):** ① 호텔측 = **벤더 콘솔 `Group RFP`** — 견적 제출·취소규정 선택·결제마감·낙찰 컨펌/거절·정산 요약. 확정 건은 콘솔 **`Billings`에 정산 라인으로 편입**(호텔 수령액·15일 주기·GROUP 배지). ② 셀러측 = **Marketplace** — 견적 선택 시 **Bookings에 리퀘스트 예약 생성**(status `Requested`·`GROUP` 배지·Twin×5,Single×5[10]·고객가), 호텔 컨펌 시 **`Confirmed`**, 상세에 **정산 요약**(고객 결제→OMH / 호텔 지불←OMH / 마진). 두 앱은 동일 문의(GRP-…)로 연계.

| **호텔 셀프(고도입 국가)** | **벤더 콘솔 `Group RFP` 화면**(별도 repo `Console`, 구현됨) — 호텔이 RFP 수신·경쟁 견적 직접 제출. KR 등 콘솔 도입률 높은 곳부터 적용. §5-0 참조 |
| **확장** | 앵커 거리 자동계산(지도) · 범위별 마크업 · **ELLIS API 연동**(현재 실연동은 브라우저 공용 저장소 버스 — §6-3) · 리퀘스트 예약↔ELLIS 연동 · 알림(메일·푸시) · 임시저장(Draft) |

## 10. 기존 규칙과의 관계 (제약)

1. **그룹 예약 = 5실 이상**(2026-10-01 확정). 약관 제4조 ③(현행 "4실 이상")은 **5실로 개정 필요**(Legal). 단체 문의 견적·리퀘스트 예약의 취소는 **호텔 지정 취소 마감** 기준.
2. **즉시 예약 4실까지** — 5실 이상은 즉시 예약 불가, **"5실 이상? 단체 문의 →"** 로 연결(Create Booking·룸리스트).
3. **취소는 예약 전체 단위**(부분취소 미지원, 전사 정책) — 리퀘스트 예약도 동일.
